# RECIPE: webrtc-src-min

How the `main-min` branch of this repository was made from upstream, and
everything that differs from it. It is the WebRTC submodule of [webrtc-min](https://github.com/komakai/webrtc-min), which builds the Android library `libjingle_peerconnection_so.so` with CMake instead of gn.

## Upstream

- Repository: https://webrtc.googlesource.com/src.git
- Revision: b9d2649d7eaf03f013b07cd9b93db73b1e4921af (2026-10-01T23:53:35-07:00)

The first commit on `main-min` is an unmodified snapshot of that revision, so
`git diff <first commit> main-min` shows every change made here.

## Deviations from upstream

- **Building without software video codecs** (commit "Allow building without
  software video codecs"): with `WEBRTC_NO_SOFTWARE_VIDEO_CODECS` defined,
  `sdk/android/src/jni/software_video_{encoder,decoder}_factory.cc` return
  factories with no formats instead of the built-in libvpx/libaom/dav1d ones,
  so those libraries aren't needed and video relies on MediaCodec.
- **Pregenerated headers** (commit "Add pregenerated JNI and field-trial
  headers"), checked in at the paths the code includes them from so the build
  needs no python, JDK or Android SDK:
  - `sdk/android/generated_*_jni/` and `rtc_base/base_java_jni/`: JNI headers
    that gn generates with `third_party/jni_zero/jni_zero.py` from the Java
    sources (`--enable-safe-pointers --use-proxy-hash`) and, for framework
    classes (`generated_external_classes_jni`), from android-37.0's
    `android.jar`.
  - `experiments/registered_field_trials.h`, generated by
    `experiments/field_trials.py header`.

  There are none for the software video codecs' JNI classes (libvpx, libaom,
  dav1d), as this build has no software codecs. To regenerate them for a new
  revision, run webrtc-min's `fetch_webrtc_android.sh` (with
  `SOFTWARE_VIDEO_CODECS=0 PROTOBUF=0`) at that revision, build
  `libjingle_peerconnection_so` with gn/ninja, and copy
  `out/android_arm64/gen/jni_headers/{rtc_base,sdk}/` and
  `out/android_arm64/gen/experiments/registered_field_trials.h` here. The
  headers must match the Java side the app is built with (the hashed `J.N`
  proxy names come from the same generator run).
- **`sdk/android/android_only_jni_exports.lst`**: Chromium's
  `build/android/android_only_jni_exports.lst` (the linker version script
  that exports only `JNI_OnLoad` and `Java_*`), without its two Chromium-only
  symbols.
- **CMake instead of gn** (commit "Add CMake build"): `CMakeLists.txt` at the
  root and one per top-level directory (per subdirectory under `modules/`),
  each an OBJECT library listing the sources of the gn targets
  `//sdk/android:libjingle_peerconnection_so` depends on, for Android arm64,
  armeabi-v7a, x86 and x86_64 (CPU-specific files are inside
  `if(WEBRTC_CPU ...)`, with the x86 SIMD files' `-msse2`/`-mavx2 -mfma`).
  `sdk/CMakeLists.txt` also defines the shared library. Like gn, which links
  every object into it with `--whole-archive`, all of WebRTC's objects are
  linked and `--gc-sections` drops unused code.
  - `webrtc_config` carries the defines gn's configs set for this build (the
    `rtc_*` gn args: no software video codecs, no protobuf, no Rust), plus the
    few gn sets only on some targets (e.g. `WEBRTC_HAVE_DCSCTP`,
    `WEBRTC_APM_DEBUG_DUMP=0`); each was checked to be unused by files outside
    those targets.
  - Only Android is supported: no iOS/desktop sources or flags, software
    video codecs, protobuf (so no RtcEventLog output or audio debug dumps),
    Rust, tests or tools.

## Updating to a new upstream revision

`main-min` isn't a git fork of upstream (no upstream history), so updates are
re-applied rather than merged:

1. Replace the tree with upstream at the new revision and commit it as
   "Snapshot of upstream at <rev>" (`git rm -rq . && git archive` of the new
   revision, or a copy of a fresh checkout).
2. Re-run the strip commands above and commit.
3. Re-apply the deviation commits (`git cherry-pick` them from the previous
   `main-min` history) and fix up any conflicts.
4. Update the source lists in the CMake files for files upstream added,
   removed or renamed (compare with the new BUILD.gn in the snapshot commit),
   then build webrtc-min and compare with a gn build.
